# synop-fill

ระบบช่วยกรอกรายงานผลการตรวจอากาศ บริเวณภาคใต้ฝั่งตะวันออก (21 สถานี รอบ 07.00 / 10.00 / 13.00 / 16.00 น.)
กรอกทีละสถานีจากหน้า METNET แล้วดูผลใน Excel จำลอง ก่อนบันทึกเป็นไฟล์ `.xlsx` ตามไฟล์ต้นแบบเดิม

> เอกสารออกแบบและกฎการถอดรหัสทั้งหมดอยู่ที่ [`docs/decoding-rules.md`](docs/decoding-rules.md)

## ระบบนี้ทำงานอย่างไร

เป็นเว็บแอปที่รันบนเครื่องเดียว (FastAPI + uvicorn) เปิดดูผ่านเบราว์เซอร์ที่ `http://localhost:8765/`
ฝั่ง Python ถอดรหัส SYNOP ตรวจค่า และสร้างไฟล์ Excel ส่วนหน้าเว็บ (Tailwind + JavaScript ธรรมดา) ทำแค่แสดงผล
ไม่ต้องใช้ Node, Tailwind หรืออินเทอร์เน็ตในเครื่องที่ใช้งานจริง ระบบไม่เก็บข้อมูลรายงานไว้เลย

## ติดตั้งครั้งแรก (Windows) ทีละขั้น

### สิ่งที่ต้องมี

| ต้องมี | หมายเหตุ |
|---|---|
| Windows 10 ขึ้นไป | ทดสอบบน Windows 10/11 |
| **Python 3.12 ขึ้นไป** | จำเป็น |
| Git | ใช้ดึงโค้ด (ถ้าได้รับโค้ดเป็น zip ไม่ต้องใช้) |
| อินเทอร์เน็ต (เฉพาะตอนติดตั้งครั้งแรก) | เพื่อโหลดแพ็กเกจ Python ถ้าไม่มี ดู[เครื่องไม่มีอินเทอร์เน็ต](#เครื่องไม่มีอินเทอร์เน็ต) |
| Docker Desktop | **ไม่จำเป็น** ใช้เฉพาะโหมดเสริม |

### ขั้นที่ 1 ติดตั้ง Python

1. ดาวน์โหลด Python 3.12 หรือใหม่กว่าจาก <https://www.python.org/downloads/>
2. ตอนติดตั้ง **ติ๊ก "Add python.exe to PATH"** ที่หน้าแรกของตัวติดตั้ง แล้วกด Install Now
3. เปิด Command Prompt แล้วตรวจว่าใช้ได้

   ```
   python --version
   ```

   ต้องขึ้น `Python 3.12.x` หรือสูงกว่า (ถ้าขึ้นเลขต่ำกว่าหรือไม่พบคำสั่ง ให้ติดตั้งใหม่ตามขั้นข้างบน)

### ขั้นที่ 2 ดึงโค้ด

```
git clone git@github.com:kanjicool/synop-fill.git
cd synop-fill
```

(ถ้าไม่ได้ตั้ง SSH key ใช้ `https://github.com/kanjicool/synop-fill.git` แทน หรือดาวน์โหลดเป็น zip แล้วแตกไฟล์)
ควรวางโฟลเดอร์ไว้ที่ที่ถาวร เช่น `D:\synop-fill` ชื่อโฟลเดอร์เป็นภาษาไทยหรือมีเว้นวรรคได้

### ขั้นที่ 3 เปิดระบบ

ดับเบิลคลิก **`script\run-app.bat`** แค่นี้ ครั้งแรกสคริปต์จะทำให้เองทั้งหมด

1. สร้างสภาพแวดล้อม Python ในโฟลเดอร์ `.venv`
2. ติดตั้งแพ็กเกจจาก `requirements.txt` (ใช้เวลาประมาณครึ่งนาที)
3. สร้างไฟล์ `.env` จาก `.env.example` (port 8765, เปิดเฉพาะเครื่องนี้)
4. ตรวจว่า port ว่าง แล้วรันระบบเบื้องหลัง
5. เปิดเบราว์เซอร์ไปที่ `http://localhost:8765/`

ครั้งต่อไปไม่ต้องติดตั้งซ้ำ เปิดเสร็จภายในไม่กี่วินาที

### ขั้นที่ 4 ลองใช้งาน

บนหน้าแรกกด **"ดูตัวอย่างที่กรอกไว้แล้ว"** (หรือเปิด `http://localhost:8765/#demo`) จะเห็นข้อมูลสมมติครบทุกสถานะ
ใช้ฝึกได้ ระบบไม่ให้บันทึกไฟล์จากโหมดนี้

### ขั้นที่ 5 (ไม่บังคับ) ตั้งค่าเพิ่ม

- เปลี่ยน port ถ้าชนกับโปรแกรมอื่น ดู[ตั้งค่า port](#ตั้งค่า-port-และการเข้าถึง)
- ให้ขึ้นเองเมื่อเข้า Windows ดู[ให้ขึ้นเองเมื่อเปิดเครื่อง](#ให้ขึ้นเองเมื่อเปิดเครื่อง)
- เปิดเอกสารไฟล์ต้นแบบ: ไฟล์ Excel ต้นแบบอยู่ที่ `templates/template.xlsx` (แก้ได้ ดู[สำหรับผู้พัฒนา](#สำหรับผู้พัฒนา))

## วิธีรันโปรเจกต์

| ต้องการ | วิธี |
|---|---|
| เปิดระบบ (เบื้องหลัง ไม่มีหน้าต่างค้าง) | ดับเบิลคลิก `script\run-app.bat` เปิดซ้ำได้ ไม่เปิดซ้อน |
| หยุดระบบ | ดับเบิลคลิก `script\stop-app.bat` |
| ดูว่ารันอยู่ไหม | `powershell -NoProfile -ExecutionPolicy Bypass -File script\app.ps1 status` หรือเปิด `http://localhost:8765/health` ต้องได้ `{"status":"ok","app":"synop-fill"}` |
| รันแบบเห็น log สด (หน้าต่างเดียว) | Git Bash: `./script/run-app` (หยุดด้วย Ctrl+C) |
| รันด้วยมือเอง | `.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8765` |
| ดู log ย้อนหลัง | ไฟล์ `logs\app.log` และ `logs\app.err.log` |
| Linux / macOS | `./script/setup` แล้ว `./script/run-app` |

รันเบื้องหลังหมายถึง `script\run-app.bat` เรียก `script\app.ps1 start` ซึ่งสั่ง
`python -m uvicorn app.main:app` แบบซ่อนหน้าต่าง รอจน `/health` ตอบ แล้วจึงเปิดเบราว์เซอร์

## วิธีใช้ (สำหรับเจ้าหน้าที่)

1. ดับเบิลคลิก **`script\run-app.bat`** เบราว์เซอร์จะเปิดหน้าระบบขึ้นมา
2. เลือกไฟล์ Excel รอบก่อน (ถ้าเป็นรอบแรกของวันไม่ต้องเลือก) แล้วกด **เริ่มต้นใช้งาน**
3. กรอกทีละสถานี: เปิดหน้าข้อมูลของสถานีนั้นใน METNET แล้วคัดลอกกล่อง "รหัสข่าว" มาวาง พิมพ์ฝน 3 ชม. และฝนสะสม
   ระบบถอดทิศลม กำลังลม ท้องฟ้า ลักษณะอากาศ และอุณหภูมิให้ ถ้าจำรหัสไม่ได้ดูคำอธิบายทีละกลุ่มใต้ฟอร์ม
4. ครบแล้วตรวจใน Excel จำลอง (แก้ได้ทุกช่อง) ช่องสีแดงต้องแก้ก่อน ช่องสีเหลืองคือคำเตือนให้ตรวจ
5. กด **ยืนยัน ไปบันทึกไฟล์** ตรวจวัน/เวลา แล้วกด **บันทึกไฟล์ Excel** ชื่อไฟล์ตั้งให้เอง แก้ได้
   (รูปแบบ `รายงานผลการตรวจอากาศเวลา HH.00 น. DD-MM-YY.xlsx` ปีพุทธศักราช 2 หลัก)

ใช้ปุ่ม "ข้าม" ถ้าสถานีไหนไม่มีข้อมูล ระบบจะแจ้งรายชื่อสถานีที่ขาดตอนบันทึก

## ตั้งค่า port และการเข้าถึง

ไฟล์ `.env` (สคริปต์สร้างให้เองครั้งแรก หรือคัดลอกจาก `.env.example`)

```
SYNOP_PORT=8765        # port ที่ใช้เปิดเบราว์เซอร์ ถ้าชนกับโปรแกรมอื่นให้เปลี่ยนเลข (1024-65535)
SYNOP_BIND=127.0.0.1   # เปิดได้เฉพาะเครื่องนี้ (แนะนำ เพราะระบบไม่มีการล็อกอิน)
```

แก้แล้วต้องหยุดและเปิดระบบใหม่ (`stop-app.bat` แล้ว `run-app.bat`)

สคริปต์ตรวจ port ทุกครั้งที่เปิด ถ้ามีโปรแกรมอื่นใช้อยู่จะแจ้งเป็นภาษาไทยและไม่เปิดระบบ ระบบไม่เลือก port อื่นให้เอง
(เพื่อไม่ให้ลิงก์/shortcut ที่ผู้ใช้บันทึกไว้ใช้ไม่ได้) ถ้าอยากรู้ว่า port ไหนว่าง

```
netstat -ano | findstr LISTENING
netsh interface ipv4 show excludedportrange protocol=tcp
```

(คำสั่งที่สองแสดงช่วง port ที่ Windows สำรองไว้ให้ Hyper-V/WSL ห้ามใช้ช่วงเหล่านั้น)

เปลี่ยน `SYNOP_BIND` เป็น `0.0.0.0` เฉพาะเมื่อต้องการให้เครื่องอื่นในเครือข่ายเข้าได้ **ระบบไม่มีการล็อกอิน**
ควรให้ไอทีกำหนด IP คงที่ เปิด Firewall เฉพาะ port นี้ และพิจารณาเพิ่มการยืนยันตัวตน

## ให้ขึ้นเองเมื่อเปิดเครื่อง

สำหรับเครื่องกลางที่เปิดทิ้งไว้ ดับเบิลคลิก `script\install-autostart.bat` จะสร้าง shortcut ในโฟลเดอร์ Startup
ของผู้ใช้ปัจจุบัน (ไม่ต้องใช้สิทธิ์ผู้ดูแลระบบ) ระบบจะเปิดเองเมื่อเข้า Windows แบบไม่เปิดเบราว์เซอร์ เลิกด้วย `script\remove-autostart.bat`

> autostart ทำงานตอนที่ผู้ใช้เข้า Windows ถ้าเครื่องรีสตาร์ตเองแล้วไม่มีใครเข้าระบบ ระบบจะยังไม่ขึ้น
> ให้ตั้ง auto-login หรือใช้ Task Scheduler

## โหมด Docker (เสริม)

ใช้เมื่ออยากแยกสภาพแวดล้อม ไม่จำเป็นสำหรับการใช้งานปกติ

1. ติดตั้ง Docker Desktop (Windows 10 ต้อง 22H2 ขึ้นไป) และเปิดให้ทำงานก่อน
2. ใช้ไฟล์ `.env` ชุดเดียวกับโหมดปกติ (port เดียวกัน)
3. ดับเบิลคลิก `script\docker-start.bat` หรือรัน `docker compose up -d --build` ในโฟลเดอร์โปรเจกต์
4. เปิด `http://localhost:8765/`
5. หยุดด้วย `script\docker-stop.bat` หรือ `docker compose down`

container ตั้ง `restart: unless-stopped` และมี healthcheck ที่ `/health`
ถ้าอยากให้ขึ้นเองเมื่อเปิดเครื่อง ต้องตั้งให้ Docker Desktop เริ่มตอนเข้า Windows ด้วย
อย่าเปิดโหมด venv กับ Docker พร้อมกัน เพราะใช้ port เดียวกัน

## เครื่องไม่มีอินเทอร์เน็ต

บนเครื่องที่ต่อเน็ตได้ ดาวน์โหลดไฟล์แพ็กเกจไว้ก่อน

```
pip download -r requirements.txt -d vendor\wheels
```

คัดลอกโฟลเดอร์โปรเจกต์ (รวม `vendor\wheels`) ไปยังเครื่องปลายทาง สคริปต์จะติดตั้งจาก `vendor\wheels` เองโดยไม่ใช้เน็ต
(ต้องดาวน์โหลดด้วย Python รุ่นและระบบปฏิบัติการเดียวกับเครื่องปลายทาง)

## ความปลอดภัยและข้อมูล

- ระบบ **ไม่เก็บข้อมูลรายงานไว้เลย**: ไฟล์ที่อัปโหลดประมวลผลในหน่วยความจำแล้วทิ้ง ไม่มีฐานข้อมูล log เก็บเฉพาะ path/สถานะ ไม่เก็บรหัสข่าวหรือค่าในตาราง
- เครื่องกลางที่หลายคนผลัดกันใช้: หน้าเว็บไม่จำข้อมูลรอบก่อน (ไม่ใช้ `localStorage`) ปุ่ม "เริ่มรอบใหม่" ล้างทุกอย่าง
- ไฟล์ Excel ที่บันทึกอยู่ในโฟลเดอร์ดาวน์โหลดของเบราว์เซอร์ เหมือนไฟล์ที่ดาวน์โหลดทั่วไป
- ค่าเริ่มต้นผูกกับ `127.0.0.1` เท่านั้น ดู[ตั้งค่า port และการเข้าถึง](#ตั้งค่า-port-และการเข้าถึง)

## สำหรับผู้พัฒนา

### เตรียมเครื่องพัฒนา

```bash
git clone git@github.com:kanjicool/synop-fill.git && cd synop-fill
./script/setup --dev                 # สร้าง .venv + ติดตั้ง pytest, httpx, openpyxl (Git Bash บน Windows)
```

ไม่มี Git Bash ใช้คำสั่งตรง ๆ ได้ (PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
```

### คำสั่งที่ใช้บ่อย

```bash
.venv/Scripts/python -m pytest                                  # ทดสอบทั้งหมด (Linux/macOS: .venv/bin/python)
./script/run-app                                                # รันระบบ ดู log สด
./script/build-css                                              # คอมไพล์ Tailwind -> web/app.css (ดาวน์โหลด standalone CLI ครั้งแรก) แล้ว commit ไฟล์ผลลัพธ์
.venv/Scripts/python script/make_template.py "<ไฟล์รายงานที่กรอกแล้ว>.xlsx"   # สร้าง templates/template.xlsx ใหม่
```

ทดสอบหน้าเว็บด้วย Chrome จริง (ต้องเปิดระบบก่อนที่ `http://127.0.0.1:8765`)

### โครงสร้างโปรเจกต์

```
app/         ตรรกะทั้งหมดฝั่ง Python
  config.py    ค่าคงที่ ตารางสถานี ตัวเลือก dropdown เกณฑ์ตรวจ (ที่เดียวที่ต้องแก้เมื่อเกณฑ์เปลี่ยน)
  decoder.py   ถอดรหัส SYNOP และอธิบายรหัสทีละกลุ่ม
  rain.py      แปลงค่าฝน (ตัวเลข / T / -) เป็นจำนวนเต็มหน่วย 0.1 มม.
  validator.py report.py   ตรวจค่า สรุปรอบ วันที่ ชื่อไฟล์ คำเตือน
  excel.py     อ่าน/เขียน .xlsx โดยแก้ XML ตรง ๆ
  main.py      FastAPI และ API ทั้งหมด
web/         หน้าเว็บ (index.html, app.js, app.css ที่คอมไพล์แล้ว)
templates/   ไฟล์ Excel ต้นแบบ (ว่าง)
script/      สคริปต์เปิด/ปิด/ติดตั้ง (.bat สำหรับ Windows, bash สำหรับ Linux/macOS/Git Bash)
tests/       pytest + ไฟล์ตัวอย่างรายงานสมมติ 3 รอบใน tests/fixtures (สร้างด้วย tests/make_fixtures.py) + ทดสอบเบราว์เซอร์ใน tests/e2e
docs/        เอกสารออกแบบ
```

### แนวคิดสำคัญ

- ตรรกะทั้งหมดอยู่ฝั่ง Python หน้าเว็บส่งสถานะทั้งหมดไปที่ `/api/check` ทุกครั้ง (stateless) ไม่เก็บข้อมูลที่ server
- Excel แก้ XML ใน `.xlsx` ตรง ๆ (ไม่ใช้ openpyxl เขียน) เพราะไฟล์มีกล่องข้อความวันที่ รูป และ dropdown ที่ openpyxl ทำหาย
- ค่าฝนคำนวณเป็นจำนวนเต็มหน่วย 0.1 มม. ไม่ใช้ float
- เทสต์: unit (ถอดรหัส ฝน ตรวจค่า), API, และ golden test ที่เทียบไฟล์ที่ระบบสร้างกับไฟล์ตัวอย่างสมมติ 3 รอบ ทุกเซลล์ (`tests/fixtures`) สร้างไฟล์ตัวอย่างใหม่ด้วย `.venv/Scripts/python tests/make_fixtures.py`
- ฟอนต์หน้าเว็บใช้ที่มีในเครื่อง (Leelawadee UI / Tahoma) ระบบจึงทำงานออฟไลน์ได้ ไม่ดึงอะไรจากอินเทอร์เน็ตตอนใช้งาน

### API

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| GET | `/health` | ตรวจว่าระบบทำงาน `{"status":"ok","app":"synop-fill"}` |
| GET | `/api/config` | สถานี ตัวเลือก dropdown ตารางอ้างอิง |
| GET | `/api/demo` | ข้อมูลตัวอย่าง |
| POST | `/api/decode` | ถอดรหัส SYNOP ของสถานีหนึ่ง พร้อมคำอธิบายรายกลุ่ม |
| POST | `/api/check` | ตรวจทั้งตาราง สรุปรอบ วัน ชื่อไฟล์ คำเตือน |
| POST | `/api/prev-file` | อ่านไฟล์ Excel รอบก่อน (ค่า H รอบ วันที่) |
| POST | `/api/export` | สร้างไฟล์ `.xlsx` (422 ถ้ายังมีช่องแดง) |

## ข้อจำกัดที่ทราบ

- ยังไม่ได้ทดสอบเปิดไฟล์ที่ระบบสร้างด้วย Excel ตัวจริง (ตรวจโครงสร้างด้วย openpyxl และเทียบ XML แล้ว) ครั้งแรกที่ติดตั้งให้เปิดไฟล์ที่ได้ดูหัวรายงาน รูป และ dropdown
- ค่า F/G/H (อุณหภูมิ ฝน 3 ชม. ฝนสะสม) ผู้ใช้ต้องกรอกเองตามที่ส่วนเฝ้าระวังกรอกใน METNET ระบบไม่ดึงจากเว็บ
- ww=80 "มีฝนโปรย" ไม่อยู่ใน dropdown ของไฟล์ต้นแบบ ระบบจึงให้ผู้ใช้เลือกเอง (ดู `docs/decoding-rules.md` หัวข้อ 14.3)
- โหมด Docker ยังไม่ได้ทดสอบ build จริงบนเครื่องพัฒนา (ตรวจ `docker-compose.yml` ด้วย `docker compose config` แล้ว)
- ทดสอบกับรหัสข่าวจริงเพียง 2 สถานี ควรใช้คู่ขนานกับการกรอกมือสักระยะก่อนใช้เป็นหลัก
