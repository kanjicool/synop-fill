# synop-fill — Implementation Plan

ระบบกรอกรายงานผลการตรวจอากาศ บริเวณภาคใต้ฝั่งตะวันออก จากโค้ด SYNOP ลงไฟล์ Excel อัตโนมัติ
เขียนด้วย **Python** เป็นหลัก หน้าเว็บใช้ **Tailwind CSS** รันบนเครื่องกลางด้วย **Python venv** เบื้องหลัง (โหมดหลัก) และมี **Docker** เป็นโหมดเสริม ผู้ใช้แค่ดับเบิลคลิกเพื่อเปิด

---

## 0. สถานะการพัฒนา (อัปเดต 2026-11-19)

สร้างระบบเสร็จตามแบบ 3 ขั้นที่ตกลงกัน (เริ่มต้น → กรอกทีละสถานี แล้วตรวจใน Excel จำลอง → บันทึกไฟล์) วิธีใช้และติดตั้งดูที่ `README.md`

| ส่วน | สถานะ | หลักฐาน |
|---|---|---|
| แกนถอดรหัส ตรวจค่า อธิบายรหัส (Python) | เสร็จ | `app/decoder.py`, `validator.py`, `report.py`, `rain.py` |
| อ่าน/เขียน Excel โดยแก้ XML ตรง ๆ | เสร็จ | `app/excel.py` + golden test เทียบไฟล์กรอกมือ 3 รอบ ทุกเซลล์ |
| API (stateless) | เสร็จ | `app/main.py` ดูหัวข้อ 7 |
| หน้าเว็บ Tailwind + vanilla JS | เสร็จ | `web/` ทดสอบด้วย Chrome จริง `tests/e2e/e2e.js` |
| เปิดใช้ด้วย venv (หลัก) | เสร็จ | `script/*.bat`, `script/app.ps1`, `./script/run-app` ทดสอบเครื่องสะอาดและโฟลเดอร์ชื่อไทย |
| โหมด Docker (เสริม) | เขียนแล้ว **ยังไม่ได้ทดสอบ build** | Docker Desktop ไม่ได้เปิดบนเครื่องพัฒนา ตรวจแค่ `docker compose config` |
| ทดสอบ | 128 test ผ่าน (unit, API, golden) + e2e ในเบราว์เซอร์ผ่านครบ | `pytest` |

**ที่ตัดสินใจต่างจากแผนเดิมระหว่างทำ**
- **`n/a` (ทิศลม `//`) เป็นคำเตือนสีเหลือง ไม่ใช่ช่องแดง** เพราะ `n/a` คือค่าที่ถูกต้องตามกระดาษเมื่อเครื่องวัดลมเสีย ถ้าเป็นช่องแดงจะบันทึกไฟล์ไม่ได้เลยในวันที่เครื่องเสีย
- **ไม่ใช้ openpyxl เขียนไฟล์** เพราะทิ้งกล่องข้อความวันที่/เวลา (หัวข้อ 14.1)
- **ค่า F/G/H ใช้ที่ผู้ใช้กรอกจาก METNET** (หัวข้อ 14.5) ระบบเตือนเมื่อ H เดิม + G ไม่เท่ากับ H และเมื่ออุณหภูมิต่างจากรหัสข่าว
- **ฟอนต์หน้าเว็บใช้ที่มีในเครื่อง** (Leelawadee UI / Tahoma) ไม่ใช่ Sarabun เพื่อให้ทำงานออฟไลน์โดยไม่ต้องแจกไฟล์ฟอนต์
- รอบที่ระบบรู้จะนับสถานีที่กำลังกรอกอยู่ด้วย (ไม่ต้องกดถัดไปก่อน) เพื่อแสดงค่า H รอบก่อนตั้งแต่สถานีแรก

**ยังไม่ได้ทำ / ต้องตรวจเอง**
1. เปิดไฟล์ที่ระบบสร้างด้วย **Excel ตัวจริง** ดูหัวรายงาน รูป dropdown (ตรวจโครงสร้างด้วย openpyxl และเทียบ XML แล้วเท่านั้น)
2. ทดสอบ **รีสตาร์ตเครื่องจริง** ว่า autostart ขึ้นเอง และ build/รัน Docker จริง
3. **ใช้งานคู่ขนาน 1 สัปดาห์** เทียบกับการกรอกมือ (Phase 5) และเก็บข้อความ SYNOP จริงให้ครบอย่างน้อย 5 รอบ (ตอนนี้มีข้อความจริงแค่ 2 สถานี)
4. คำถามค้างหัวข้อ 14.6: ป้าย "ดูฉบับ SMTHxx" และ Ctrl+A/Ctrl+C บนหน้ารายละเอียดสถานี (ถ้าวางได้ ต่อยอดเป็นช่องวางหลายสถานีครั้งเดียวได้)
5. ww อื่นนอกตาราง (เช่น 51–59, 80, 96) และ ww ของสถานีอัตโนมัติ (iX = 4/7) ตรวจจากข้อมูลจริง

## 1. ภาพรวม

### ปัญหาเดิม
- เปิดเว็บ METNET แล้วเลือกสถานีทีละสถานี
- ตีความโค้ด SYNOP ด้วยตนเองโดยเทียบกับตารางในกระดาษ
- พิมพ์ทิศลม กำลังลม ท้องฟ้า ลักษณะอากาศ อุณหภูมิ และฝน ลง Excel ทีละช่อง
- ใช้เวลานานและพิมพ์ผิดได้ง่าย โดยเฉพาะค่าฝนสะสม

### เป้าหมาย
- วางข้อความ SYNOP ทุกสถานีครั้งเดียว ระบบถอดรหัสและกรอกลง Excel ให้เอง
- เติมข้อมูลลงไฟล์ต้นแบบเดิม โดยฟอนต์ เส้นตาราง และลำดับสถานียังเหมือนเดิม
- ตั้งชื่อไฟล์ให้อัตโนมัติ และแก้ชื่อเองได้
- ตรวจหาค่าผิดปกติ และให้ผู้ใช้ตรวจก่อนบันทึกทุกครั้ง
- **ผู้ใช้ไม่ต้องรันคำสั่งเอง** ดับเบิลคลิกไฟล์เดียวแล้วเบราว์เซอร์เปิดหน้าระบบขึ้นมา
- **รองรับ 2 วิธีรัน ด้วยโค้ดชุดเดียวกัน:** (1) **Python venv ผ่าน `script/run-app` — โหมดหลัก** (เครื่องกลางเป็น Windows 10 ติดตั้ง Python ได้เอง) (2) Docker container — โหมดเสริม เตรียมไว้เผื่อย้ายเครื่องหรืออยากแยกสภาพแวดล้อม

## 2. Tech Stack

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| Backend / ตรรกะทั้งหมด | **Python ≥ 3.12 + FastAPI + uvicorn** | ถอดรหัส คำนวณฝน ตรวจค่า และอ่าน/เขียน Excel อยู่ฝั่ง Python ทั้งหมด เทสต์ได้ง่าย |
| อ่าน/เขียน Excel | **แก้ไฟล์ `.xlsx` ที่ระดับ XML** (`zipfile` + `xml.etree`/`lxml`) | ไฟล์จริงมี **กล่องข้อความวันที่/เวลา** และรูปฝังอยู่ ซึ่ง `openpyxl` ทิ้งตอนบันทึก การแก้เฉพาะ XML ของเซลล์ที่ต้องแก้ทำให้ทุกอย่างอื่น (ฟอนต์ เส้น dropdown กล่องข้อความ รูป) คงเดิม 100% (ใช้ `openpyxl` อ่านค่าในเทสต์ได้) |
| ตัวเลขฝน | `decimal.Decimal` | หลีกเลี่ยงปัญหา float เช่น 0.1 + 0.2 ทำให้ฝนสะสมเพี้ยน |
| หน้าเว็บ | **HTML + Tailwind CSS** + JavaScript เล็กน้อย | ดูหัวข้อ 2.1 |
| ทดสอบ | **pytest** | unit test ของตัวถอดรหัส และ golden test เทียบไฟล์ Excel |
| รันระบบ (หลัก) | **Python venv** + `script/run-app` | ติดตั้งง่ายบน Windows 10 ไม่ต้องพึ่ง virtualization ดูหัวข้อ 2.3 และ 12.7 |
| รันระบบ (เสริม) | **Docker + Docker Compose** | ใช้เมื่อย้ายเครื่อง/อยากแยกสภาพแวดล้อม ดูหัวข้อ 2.2 และ 12 |

### 2.1 แนวทางฝั่งหน้าเว็บ (Python ก่อน JS เมื่อจำเป็น)
- **ตรรกะทุกอย่างอยู่ที่ Python** เบราว์เซอร์ไม่ถอดรหัสเอง แค่ส่งข้อความไปที่ API แล้วแสดงผลที่ได้กลับมา
- **ใช้ JS เฉพาะส่วนที่ Python ทำไม่ได้หรือยุ่งยาก** คือ
  - ตารางตรวจทานที่แก้ค่าในช่องได้ทันที เปลี่ยนสีช่อง/แถวตามสถานะ
  - ส่งข้อมูลที่แก้แล้วไปสร้างไฟล์ แล้วสั่งดาวน์โหลด
  - เขียนเป็น vanilla JS ไฟล์เดียว (`web/app.js`) ไม่ใช้ framework และไม่ต้องมี Node ในเครื่องใช้งาน
- **Tailwind ต้องใช้งานแบบออฟไลน์ได้** (เครือข่ายราชการอาจบล็อก CDN) จึง **ห้ามใช้ `cdn.tailwindcss.com`**
  - ฝั่งผู้พัฒนารัน `script/build-css` (Tailwind standalone CLI ไบนารีเดี่ยว ไม่ต้องติดตั้ง Node) เพื่อคอมไพล์ `web/input.css` เป็น `web/app.css`
  - **commit `web/app.css` เข้า repo** ทั้ง Docker และ venv แค่เสิร์ฟไฟล์นี้ ผู้ใช้จึงไม่ต้องมี Tailwind, Node หรืออินเทอร์เน็ต
  - ถ้าแก้ class ใน `index.html` / `app.js` ต้องรัน `script/build-css` ใหม่ก่อน commit ทุกครั้ง
- ฟอนต์ภาษาไทยของหน้าเว็บ: เก็บไฟล์ฟอนต์ไว้ใน `web/fonts/` ไม่ดึงจาก Google Fonts

### 2.2 โหมดเสริม: Docker
- image เดียว บรรจุทั้ง API หน้าเว็บ และไฟล์ต้นแบบ
- ตั้ง `restart: unless-stopped` ให้ container ขึ้นเองหลังเปิดเครื่อง (เมื่อ Docker Desktop ตั้งให้เปิดอัตโนมัติ)
- เครื่องใช้งานที่เครือข่ายถูกจำกัด: build image ที่เครื่องอื่นแล้วส่งไฟล์ `docker save` ไปโหลดด้วย `docker load` ได้ ไม่ต้องให้เครื่องใช้งานต่ออินเทอร์เน็ต

### 2.3 โหมดหลัก: Python venv
- `script/setup`: สร้าง `.venv` และ `pip install -r requirements.txt` (ทำครั้งเดียว) เครื่องที่ไม่มีอินเทอร์เน็ตให้เตรียมไฟล์ wheel ไว้ใน `vendor/wheels/` แล้วติดตั้งแบบ `--no-index --find-links`
- `script/run-app`: ถ้ายังไม่มี `.venv` ให้เรียก `script/setup` เอง → อ่าน `.env` → ตรวจ port → สตาร์ต uvicorn (รันค้างในหน้าต่างเดียว เหมาะตอนพัฒนา/ดู log)
- `script\run-app.bat` (Windows ดับเบิลคลิก): ทำเหมือนกันแต่ **รันเบื้องหลังโดยไม่มีหน้าต่างค้าง** แล้วเปิดเบราว์เซอร์ให้ ส่วน `script\stop-app.bat` ใช้หยุด และ `script\install-autostart.bat` ทำให้ระบบขึ้นเองเมื่อเข้า Windows (ดูหัวข้อ 12.7)
- **บน Windows:** PowerShell/cmd รัน `./script/run-app` ตรง ๆ ไม่ได้ (ไม่มี shebang) จึงมี `script\run-app.bat` ไว้ดับเบิลคลิก ส่วน `./script/run-app` ใช้ได้ใน Git Bash / Linux / macOS
- ต้องมี **Python 3.12 ขึ้นไป** (3.12, 3.13, …) สคริปต์ตรวจเวอร์ชันและแจ้งเป็นภาษาไทยถ้าต่ำกว่านี้ โค้ดต้องรันได้บน 3.12 ซึ่งเป็นเวอร์ชันต่ำสุด จึงห้ามใช้ฟีเจอร์ที่มีเฉพาะ 3.13+ และให้รัน pytest บน 3.12 เสมอ
- เครื่องกลางเปิดทิ้งไว้ ระบบจึงต้องรันเบื้องหลังและขึ้นเองได้ ไม่ปล่อยเป็นหน้าต่างคำสั่งที่ใครจะเผลอปิด (รายละเอียดในหัวข้อ 12.7)
- ใช้ `.env` และกฎเรื่อง port ชุดเดียวกับ Docker (หัวข้อ 12.3)

| B | ทิศทางลม | `Nddff` → `dd` | เทียบตารางทิศ (หัวข้อ 14.3) เขียนเป็น "ลม" + ชื่อทิศ / dd=00 → "ลมสงบ" เสมอ (ยืนยันแล้ว แม้ ff>0) / `99` → "ลมแปรปรวน" / `//` → "n/a" (ตัวเลือกใน dropdown ของ Excel; เตือนสีเหลือง ไม่บล็อกการบันทึก) |
| C | กำลังลม | `Nddff` → `ff` | `/ กำลังอ่อน` (≤7), `/ กำลังปานกลาง` (8–15), `/ กำลังแรง` (≥16) / ถ้าลมสงบให้เว้นว่าง |
| D | ท้องฟ้า | `Nddff` → `N` | 0 ท้องฟ้าแจ่มใส, 1–2 ท้องฟ้าโปร่ง, 3–4 เมฆบางส่วน, 5–6 เมฆเป็นส่วนมาก, 7 เมฆมาก, 8 เมฆเต็มท้องฟ้า, 9 มองไม่เห็นท้องฟ้า (ข้อความตรงตามที่กรอกในไฟล์จริง ดูหัวข้อ 14.3) |
| E | ลักษณะอากาศ | `7wwW1W2` (กลุ่มแรกที่ขึ้นต้นด้วย 7 นับจากกลุ่มที่ 4 ใน Section 1) | ใส่เมื่อ ww ≥ 04 เขียนเป็น `/ ข้อความ` / ถ้าไม่มีกลุ่ม 7 ให้เว้นว่าง |
| F | อุณหภูมิ | ช่อง "อุณหภูมิตุ้มแห้ง" ใน METNET (ส่วนเฝ้าระวังกรอก) / สำรอง: `1sTTT` | s=1 คือค่าติดลบ แสดงทศนิยม 1 ตำแหน่ง ถ้ามีรหัสข่าวด้วย ใช้ `1sTTT` เป็นค่าตั้งต้นและเตือนเมื่อต่างจากค่าที่กรอก |
| G | ฝน 3 ชม. | ช่อง "ปริมาณฝน 3 ชม." ใน METNET (ส่วนเฝ้าระวังกรอก) | ตัวเลข / `T` / `-` (ตกลงแล้ว: ใช้ค่าที่เขากรอก ไม่ถอดจากกลุ่ม `6RRRtR` เอง ดูหัวข้อ 14.5) |
| H | ฝนสะสมวันนี้ (รอบ 07.00 = ฝน 24 ชม.) | ช่อง "ฝนตั้งแต่ 00 UTC" ใน METNET (รอบ 07.00: ช่อง "ฝน 24 ชม.") | ใช้ค่าที่เขากรอก แล้วตรวจกับ H เดิม + G เป็นการเตือน (ไม่ใช่การคำนวณ) |

**หมายเหตุการเขียนเซลล์:** ค่าที่เป็นตัวเลข (F, G, H) ต้องเขียนเป็นตัวเลขจริงพร้อม `number_format = "0.0"` ส่วนค่า `T` และ `-` เขียนเป็นข้อความ

## 5. กฎการถอดรหัสที่ต้องรองรับ

### 5.0 ตำแหน่งกลุ่มที่อ่านค่า (ตกลงแล้ว)
นับกลุ่มของแต่ละสถานีโดยให้รหัสสถานี `IIiii` เป็นกลุ่มที่ 1
- **กลุ่มที่ 3 = `Nddff`** อ่านท้องฟ้า (N) ทิศลม (dd) และกำลังลม (ff) จากกลุ่มนี้กลุ่มเดียว เช่น `48552 32460 60504 ...` กลุ่มที่ 3 คือ `60504`
- **ลักษณะอากาศ:** ไล่ดูตั้งแต่ **กลุ่มที่ 4 เป็นต้นไป** หา **กลุ่มแรกที่ขึ้นต้นด้วย 7** แล้วใช้ ww (2 หลักถัดมา) เจอกลุ่มแรกแล้วหยุด ไม่ดูกลุ่ม 7 อื่น และไม่ใช้ W1W2
- **ห้ามเริ่มหาตั้งแต่กลุ่มที่ 3** เพราะ N=7 (เมฆมาก) ทำให้กลุ่ม `Nddff` ขึ้นต้นด้วย 7 ได้เหมือนกัน เช่น `70504`
- **หาเฉพาะใน Section 1** (ก่อนกลุ่มนำ `222` / `333` / `444` / `555`) เพราะหลังจุดนั้นกลุ่มที่ขึ้นต้นด้วย 7 อาจมีความหมายอื่น ไม่ใช่ลักษณะอากาศ
- ไม่พบกลุ่ม 7 → E เว้นว่าง
- **ยืนยันจากตัวอย่างจริง:** ใน Section 3 (หลัง `333`) กลุ่มที่ขึ้นต้นด้วย 7 คือ **ฝน 24 ชม.** เช่น `70270` = 27.0 มม. (ตรงกับ `RD27.0` และช่อง "ปริมาณฝน 24 ชม." ใน METNET) ไม่ใช่ลักษณะอากาศ จึงต้องไม่หาในส่วนนั้นตามกฎข้างต้น

### 5.1 ส่วนหัวข้อความ
- `AAXX YYGGiw`: ใช้ YY คือวัน และ GG คือชั่วโมง UTC แล้ว +7 เป็นเวลาไทย
- `iw` = 0 หรือ 1 หมายถึงความเร็วลมเป็น m/s ต้องแปลงเป็นนอต (×1.944)
- ff = `99` ให้อ่านความเร็วจริงจากกลุ่ม `00fff` ที่ตามมา
- ข้อความเดียวอาจมีหลายสถานี โดยแยกกันด้วย `=`

### 5.2 ตัวบ่งชี้ (กลุ่ม `iRiXhVV`)
| ตัวบ่งชี้ | ค่า | การจัดการ |
|---|---|---|
| iR | 0, 1, 2 | อ่านกลุ่ม 6 (0 = มีทั้ง Section 1 และ 3, 1 = Section 1, 2 = Section 3 หลัง `333`) — ข้อ 0 ผมเพิ่มตามรหัสมาตรฐาน WMO ตรวจกับข้อมูลจริงใน Phase 5 |
| iR | 3 | ไม่มีฝน → G = 0.0 |
| iR | 4 | ไม่ได้วัดฝน → G = `-` (ตกลงแล้ว) |
| iX | 2, 3, 5, 6 | ไม่มีกลุ่ม 7 → E เว้นว่าง (ไม่ต้องใช้ iX ตัดสิน เพราะใช้กฎหากลุ่ม 7 ตามหัวข้อ 5.0 อยู่แล้ว) |
| iX | 4, 7 | สถานีอัตโนมัติ ตามมาตรฐาน WMO ความหมายของ ww อาจต่างจากตารางบนกระดาษ ให้ตรวจใน Phase 5 ว่าสถานีไหนส่ง iX นี้ และ ww ตรงกับที่กรอกมือหรือไม่ |

### 5.3 ปริมาณฝน (RRR) — ใช้เป็นสำรอง/ตรวจสอบ

ค่า G และ H หลักมาจากช่องของ METNET ที่ส่วนเฝ้าระวังกรอก (หัวข้อ 14.5) กฎด้านล่างใช้เฉพาะเมื่อต้องถอดจากรหัสเอง
| RRR | ค่า |
|---|---|
| 000–989 | มม. ตามตัวเลข |
| 990 | **T** (ฝนน้อยกว่าจะวัดได้) |
| 991–999 | 0.1–0.9 มม. |
| `///` | ค่าเสีย/ไม่มีข้อมูล → G = `-` (ตกลงแล้ว) |

- ค้นหากลุ่มฝนที่ tR=7 (3 ชม.) ทั้งใน Section 1 และ Section 3 (`333`)
- รวมฝนสะสมโดยถือว่า T = 0 แต่ถ้าผลรวมเป็น 0 และมี T อยู่ ให้แสดงเป็น T
- **`-` คือค่าที่ใช้ได้จริง ไม่ใช่ข้อผิดพลาด** จึงไม่บล็อกการดาวน์โหลด (ถ้าเป็นช่องแดงจะบล็อก) แต่แสดงเป็นสีเหลืองอ่อนให้ผู้ใช้เห็นว่าช่องนี้ไม่มีค่าฝน และ validator ข้ามการตรวจฝนของช่องนั้น
- **ค่า H เมื่อมี `-`:** รวมเฉพาะค่าที่เป็นตัวเลข (ไม่เอา `-` ไปบวก) ถ้าไม่มีตัวเลขเลยให้ H = `-` และช่อง H ที่มี `-` อยู่ในการรวมต้องเป็นสีเหลืองอ่อนว่า "ฝนสะสมอาจไม่ครบ" (ค่าเริ่มต้น แก้ได้ใน `config.py`)
- **ถ้าไม่พบกลุ่มฝน tR=7** (และ iR ไม่ใช่ 3) → G = `-` สีเหลืองอ่อน (ใช้เฉพาะตอนถอดจากรหัสเป็นสำรอง ตัวอย่างสงขลา 13.00 น. ไม่มีกลุ่ม tR=7 เลย จึงไม่ใช้กฎนี้เป็นค่าหลัก)

### 5.4 กรณีพิเศษอื่น
- `NIL` หรือข้อความไม่ครบ → แถวเป็นสีเทา และแจ้งว่า "ไม่มีข้อมูล" (ช่องฝน G ลง `-`; ช่อง B–F เว้นว่าง)
- สถานีส่งซ้ำ → ใช้ข้อความล่าสุด และแจ้งเตือน
- รหัสสถานีที่ไม่อยู่ในไฟล์ต้นแบบ → ข้ามเงียบ ๆ และสรุปเป็นบรรทัดเดียว (เช่น "ข้าม N สถานีนอกรายงาน") ไม่แจ้งเตือนทีละสถานี เพราะข้อความจาก METNET ฉบับเดียวมีหลายสิบสถานี
- ข้อความหลายชุดที่มีเวลาต่างกัน → แจ้งเตือน
- ww ที่ไม่มีในตาราง → แสดง `[ww=xx]` เป็นช่องแดง ห้ามเดาความหมาย

### 5.5 ข้อควรระวังเฉพาะ Python
- **ห้ามใช้ `float` กับค่าฝน** ใช้ `Decimal` และแปลงเป็นตัวเลขตอนเขียนลง Excel เท่านั้น
- **กฎที่ตกลงแล้ว: ปัดนอตเป็นจำนวนเต็มแบบ `ROUND_HALF_UP` ก่อนเทียบเกณฑ์กำลังลม** ค่านอตที่แปลงจาก m/s ไม่ถูกเขียนลง Excel แต่ใช้ตัดสินข้อความในคอลัมน์ C ซึ่งเกณฑ์เป็นจำนวนเต็ม (≤7 / 8–15 / ≥16) ถ้าไม่ปัด ค่าเช่น 4 m/s = 7.776 นอต จะตกช่องว่างระหว่าง 7 กับ 8 (ปัดแล้วได้ 8 → กำลังปานกลาง)
- **ห้ามใช้ `round()` ของ Python** เพราะปัดแบบ banker's rounding (เช่น `round(2.5) == 2`) ให้ใช้ `Decimal.quantize(Decimal("1"), rounding=ROUND_HALF_UP)` และมี test กรณีขอบ เช่น ผลคูณลงท้าย .5 พอดี
- รหัสสถานีและกลุ่มรหัสเก็บเป็น **สตริง** เสมอ เพื่อไม่ให้เลขศูนย์นำหน้าหาย (เช่น `00fff`, `04`)

## 7. การออกแบบ API

ทุก endpoint **ไม่เก็บสถานะ (stateless)** ฝั่งเว็บส่งข้อมูลทั้งหมดมาทุกครั้ง ไฟล์ Excel ที่อัปโหลดประมวลผลในหน่วยความจำแล้วทิ้ง

| Method | Path | หน้าที่ |
|---|---|---|
| GET | `/` | หน้าเว็บ (`Cache-Control: no-store`) |
| GET | `/health` | ตอบ `{"status":"ok","app":"synop-fill"}` ใช้เป็น Docker healthcheck และให้สคริปต์เช็กว่า port นั้นเป็นระบบของเราเองหรือไม่ |
| GET | `/api/config` | สถานี 21 แห่ง ตัวเลือก dropdown รอบรายงาน ตารางอ้างอิงตามกระดาษ |
| GET | `/api/demo` | ข้อมูลตัวอย่างฝึกใช้ (รอบ 13.00 น. 18-11-69) |
| POST | `/api/decode` | รหัสข่าวของสถานีเดียว → ทิศลม กำลังลม ท้องฟ้า ลักษณะอากาศ อุณหภูมิ เวลาของข้อความ ปัญหา (เช่น รหัสผิดสถานี) และคำอธิบายทีละกลุ่ม |
| POST | `/api/check` | ข้อมูลทั้ง 21 สถานี → ช่องที่ต้องดู (err/warn/note) วัน/รอบล่าสุด ชื่อไฟล์ หัวรายงาน รายการที่ต้องดู และสรุป |
| POST | `/api/prev-file` | อัปโหลดไฟล์รอบก่อน → ค่า H เดิมของแต่ละสถานี รอบและวันที่จากหัวรายงาน |
| POST | `/api/export` | multipart: `payload` (JSON เดียวกับ `/api/check`), `filename` (ชื่อที่ผู้ใช้แก้ ไม่บังคับ), `template` (ไฟล์ ไม่บังคับ ถ้าไม่ส่งใช้ `templates/template.xlsx`) → ไฟล์ `.xlsx` |

**ข้อกำหนด (ทำแล้วและมี test)**
- `/api/export` **ปฏิเสธ (HTTP 422)** ถ้ายังมีช่อง "ต้องแก้" หรือยังไม่ทราบรอบ ตรวจซ้ำที่ฝั่งเซิร์ฟเวอร์ ไม่เชื่อแค่ปุ่มในหน้าเว็บ
- ชื่อไฟล์ภาษาไทยส่งใน `Content-Disposition` แบบ RFC 5987 และชื่อที่ผู้ใช้แก้ถูกล้างอักขระต้องห้าม (`\ / : * ? " < > |`) และบังคับนามสกุล `.xlsx`
- จำกัดไฟล์อัปโหลด 5 MB รับเฉพาะ `.xlsx` และตรวจว่าเป็นไฟล์รายงานนี้จริง (ต้องมี 21 สถานีในคอลัมน์ A)
- ข้อความ error เป็นภาษาไทย ไม่ส่ง stack trace ไม่เปิด `/docs` และ OpenAPI

## 12. Docker, Port และการเปิดใช้งาน

### 12.1 Dockerfile (โหมดเสริม)
- ฐาน `python:3.12-slim` → ติดตั้ง `requirements.txt` → คัดลอก `app/` และ `web/` (รวม `app.css` ที่คอมไพล์ไว้แล้วใน repo) จึงไม่ต้องมี stage สำหรับ Tailwind
- รันด้วย user ที่ไม่ใช่ root
- ตั้ง `TZ=Asia/Bangkok` เพื่อให้เวลาในระบบตรงกับเวลาไทย
- ฟังที่พอร์ต **ภายใน container คงที่ (8000)** ไม่เปลี่ยนตามเครื่อง ส่วนพอร์ตที่ผู้ใช้เปิดเบราว์เซอร์ตั้งที่ `docker-compose.yml`

### 12.2 docker-compose.yml (สาระสำคัญ)
```yaml
services:
  synop-fill:
    build: .
    image: synop-fill:latest
    container_name: synop-fill
    restart: unless-stopped            # เปิดเครื่องใหม่แล้วขึ้นเอง
    ports:
      # รูปแบบ  <ที่อยู่ที่ผูก>:<port ที่เครื่องเรา>:<port ใน container>
      - "${SYNOP_BIND:-127.0.0.1}:${SYNOP_PORT:-8765}:8000"
    environment:
      TZ: Asia/Bangkok
    volumes:
      - ./templates:/app/templates:ro  # เปลี่ยนไฟล์ต้นแบบได้โดยไม่ต้อง build ใหม่
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request as u; u.urlopen('http://127.0.0.1:8000/health')"]
      interval: 30s
      timeout: 5s
      retries: 3
```
- ไม่ใช้ `curl` ใน healthcheck เพราะ image `slim` ไม่มี ใช้ Python เรียกเองแทน

### 12.3 เรื่อง port (จุดที่ต้องระวัง)
1. **ไม่ใช้ port ที่นิยม** เพราะมีโอกาสชนสูง: 80, 443, 3000, 3306, 5000, 5173, 5432, 8000, 8080, 8888, 9000 ค่าเริ่มต้นของเราคือ **8765** (ตั้งผ่าน `SYNOP_PORT` ใน `.env` ไม่ต้องแก้ไฟล์โค้ด)
2. **port ภายใน container (8000) กับ port ที่เครื่องเปิด (8765) แยกจากกัน** ถ้า 8765 ชน แก้แค่เลขใน `.env` ที่เดียว
3. **Windows สำรอง port บางช่วงไว้ให้ Hyper-V/WSL2/Docker** ทำให้ port ในช่วงนั้นเปิดไม่ได้ทั้งที่ไม่มีโปรแกรมใช้ ตรวจด้วย
   `netsh interface ipv4 show excludedportrange protocol=tcp`
   แล้วเลือก port ที่ไม่อยู่ในช่วงเหล่านั้น (เลข 8765 ต้องตรวจในเครื่องจริงก่อนใช้ ห้ามสันนิษฐานว่าว่างเสมอ)
4. **อย่าใช้ port ช่วง 49152 ขึ้นไป** เพราะเป็นช่วงที่ Windows ใช้จัดสรรให้การเชื่อมต่อขาออก อาจชนแบบสุ่ม
5. **`script\run-app.bat` และ `docker-start.bat` ต้องตรวจ port ก่อนเริ่ม** (เช่น `Get-NetTCPConnection -LocalPort <port>`) ถ้ามีโปรแกรมอื่นใช้อยู่ ให้แจ้งเป็นภาษาไทย เช่น "port 8765 ถูกใช้งานอยู่ กรุณาเปลี่ยนเลข SYNOP_PORT ในไฟล์ .env" แล้วไม่เริ่มระบบ
6. ถ้าระบบรันอยู่แล้ว (เปิดซ้ำ) ให้ `script\run-app.bat` / `docker-start.bat` แค่เปิดเบราว์เซอร์ โดยเช็กว่า port นั้นเป็นของเราจริงจาก `/health` ที่ตอบ `"app":"synop-fill"` ไม่พยายามสตาร์ตซ้ำ และไม่รายงานว่า port ชน (เพราะ port นั้นเป็นของเราเอง)
7. ห้ามฮาร์ดโค้ด port ใน `README` `user-guide.md` หรือสคริปต์ใด ๆ ให้อ่านจาก `.env` ทั้งหมดเพื่อไม่ให้เอกสารกับของจริงไม่ตรงกัน
8. **ไม่ทราบว่าเครื่องกลางมีโปรแกรมใดใช้ port อะไรอยู่** (คำถามข้อ 11) จึงตรวจ 2 ชั้น: (ก) ตอนติดตั้งครั้งแรกรัน `netstat -ano | findstr LISTENING` และ `netsh interface ipv4 show excludedportrange protocol=tcp` แล้วจดผลไว้ (ข) สคริปต์ตรวจซ้ำทุกครั้งที่เปิด **ไม่เลือก port อื่นให้เอง** เพราะจะทำให้ bookmark/shortcut ของผู้ใช้ใช้ไม่ได้ ให้แจ้งและให้ผู้ดูแลแก้ `.env`

### 12.4 การเข้าถึงจากเครื่องอื่น (LAN)
- **กรณีใช้งานจริง (ตกลงแล้ว) ไม่ต้องใช้ส่วนนี้** ใช้เครื่องกลางเครื่องเดียว ผู้ใช้เปิดเบราว์เซอร์บนเครื่องนั้นเอง จึงคงค่าเริ่มต้น `127.0.0.1` และไม่ต้องเปิด Firewall ส่วนที่เหลือของหัวข้อนี้ไว้เผื่ออนาคต
- **ค่าเริ่มต้น `SYNOP_BIND=127.0.0.1`** เปิดได้เฉพาะเครื่องที่รัน container เนื่องจากระบบไม่มีระบบล็อกอิน
- ถ้าต้องการให้เครื่องอื่นในที่ทำงานเข้าได้ ให้เปลี่ยนเป็น `SYNOP_BIND=0.0.0.0` แล้วผู้ใช้เปิด `http://<IP เครื่อง>:<port>` (ควรให้ไอทีกำหนด IP คงที่ และอาจต้องเปิด Windows Firewall ให้ port นี้)
- ถ้าเปิด LAN ต้องพิจารณาเพิ่มการป้องกันอย่างน้อย HTTP Basic Auth ก่อนใช้งานจริง

### 12.5 docker-start.bat / docker-stop.bat (ผู้ใช้ดับเบิลคลิกอย่างเดียว)
`docker-start.bat` ทำตามลำดับ
1. อ่านค่า `SYNOP_PORT` จาก `.env` (ถ้าไม่มีไฟล์ใช้ค่าเริ่มต้น และสร้างจาก `.env.example`)
2. ตรวจว่า Docker รันอยู่ ถ้าไม่ → พยายามเปิด Docker Desktop แล้วรอ (ไม่เกิน ~2 นาที) ถ้ายังไม่ขึ้น แจ้งภาษาไทยให้ติดต่อผู้ดูแล
3. ถ้า container ยังไม่รัน → ตรวจ port (หัวข้อ 12.3 ข้อ 5) → `docker compose up -d`
4. รอจน healthcheck เป็น `healthy` (มี timeout)
5. เปิดเบราว์เซอร์ที่ `http://localhost:<port>`

`docker-stop.bat` รัน `docker compose stop` (ไม่ลบ container) ส่วนการลบทั้งหมดไม่ใส่ไว้ในไฟล์ที่ผู้ใช้เห็น

**ข้อความทุกอย่างที่แสดงในหน้าต่างคำสั่งต้องเป็นภาษาไทยที่บอกว่า "เกิดอะไรขึ้น" และ "ต้องทำอะไรต่อ" ไม่แสดง error ดิบของ Docker อย่างเดียว**

### 12.6 ทำให้ทุกอย่างอัตโนมัติที่สุดสำหรับผู้ใช้ (โหมด Docker)
- ตั้ง Docker Desktop → Settings → *Start Docker Desktop when you sign in* เพื่อให้เปิดเครื่องแล้ว container ขึ้นเองตาม `restart: unless-stopped`
- สร้าง shortcut ของ `docker-start.bat` บนหน้าจอ Desktop ตั้งชื่อ "เปิดระบบกรอกรายงานอากาศ" (ดับเบิลคลิกแล้วเข้าหน้าเว็บ ไม่ว่า container จะรันอยู่แล้วหรือไม่)
- การอัปเดตเวอร์ชัน: `update.bat` (หรือขั้นตอนใน README) ทำ `docker compose build` แล้ว `docker compose up -d` ข้อมูลไม่หายเพราะระบบไม่เก็บสถานะ

### 12.7 โหมดหลัก: Python venv (`script/run-app`)

**สคริปต์ทั้งหมด**

| สคริปต์ | หน้าที่ |
|---|---|
| `script/setup` | สร้าง `.venv` และ `pip install -r requirements.txt` (เรียกซ้ำได้ปลอดภัย) |
| `script/run-app` | รันแบบค้างหน้าต่างเดียว เห็น log ตรง ๆ ใช้ตอนพัฒนาหรือไล่ปัญหา (Git Bash/Linux/macOS) |
| `script\run-app.bat` | **ตัวที่ผู้ใช้ดับเบิลคลิก** รันเบื้องหลังไม่มีหน้าต่างค้าง แล้วเปิดเบราว์เซอร์ |
| `script\stop-app.bat` | หยุดระบบที่รันเบื้องหลัง (อ่าน PID จาก `.run/app.pid`) |
| `script\install-autostart.bat` | สร้าง shortcut ของ `run-app.bat` ใน Startup folder ของผู้ใช้ให้ระบบขึ้นเองเมื่อเข้า Windows (ไม่ต้องใช้สิทธิ์ admin) |

**ลำดับการทำงานของ `script\run-app.bat`**
1. หา Python ที่เวอร์ชัน ≥ 3.12 (ลอง `py -3.13`, `py -3.12`, แล้วค่อย `python`) ถ้าไม่เจอ → แจ้งภาษาไทยว่าต้องติดตั้งอะไร แล้วหยุด
2. ถ้าไม่มี `.venv` หรือใช้งานไม่ได้ → เรียก `script/setup`
3. อ่าน `.env` (ถ้าไม่มี สร้างจาก `.env.example`)
4. เช็ก `http://127.0.0.1:<port>/health` ถ้าตอบ `"app":"synop-fill"` แปลว่ารันอยู่แล้ว → เปิดเบราว์เซอร์แล้วจบ (ไม่เปิดซ้อน)
5. ถ้า port ถูกโปรแกรมอื่นใช้อยู่ → แจ้งตามหัวข้อ 12.3 ข้อ 5 แล้วหยุด
6. สตาร์ต `uvicorn app.main:app --host $SYNOP_BIND --port $SYNOP_PORT` แบบซ่อนหน้าต่าง บันทึก PID ลง `.run/app.pid` และ log ลง `logs/app.log` (จำกัดขนาด/หมุนไฟล์ไม่ให้โตไม่สิ้นสุด)
7. รอจน `/health` ตอบ (มี timeout) แล้วเปิดเบราว์เซอร์ที่ `http://localhost:<port>`

**ความต่างระหว่างสองโหมด**

| | venv (หลัก) | Docker (เสริม) |
|---|---|---|
| ต้องติดตั้ง | Python ≥ 3.12 | Docker Desktop (Windows 10 ต้อง 22H2 ขึ้นไป และต้องเปิด virtualization ได้) |
| ขึ้นเองหลังเปิดเครื่อง | ได้ ผ่าน `install-autostart.bat` (ทำงานตอน login) | ได้ (`restart: unless-stopped` + Docker Desktop เริ่มตอน login) |
| รันเบื้องหลัง | ได้ (`run-app.bat` ซ่อนหน้าต่าง) | ได้ |
| ชั้น port | uvicorn ฟังที่ `SYNOP_PORT` โดยตรง | map `SYNOP_PORT` → 8000 ใน container |
| จุดอ่อน | `.venv` ผูกกับ path และตัว Python | ต้องมี Docker Desktop ทำงานอยู่ |
| อัปเดตเวอร์ชัน | แทนไฟล์โปรเจกต์ แล้วรัน `script/setup` | `docker compose build` แล้ว `up -d` |
| เปิดสคริปต์ | `script\run-app.bat` | `docker-start.bat` |

ทั้งสองโหมดใช้ `.env` เดียวกัน และ `SYNOP_BIND` ค่าเริ่มต้น `127.0.0.1` เหมือนกัน (กฎตามหัวข้อ 12.4)

### 12.8 ข้อควรระวังเมื่อใช้เครื่องกลางร่วมกัน (ผลัดเวร)
- **เครื่องเปิดทิ้งไว้และมีหลายคนผลัดกันใช้ → ใช้ venv เป็นโหมดหลัก (ตกลงแล้ว) แต่ต้องทำให้ไม่มีหน้าต่างคำสั่งค้างให้ใครเผลอปิด** จึงมี `run-app.bat` แบบรันเบื้องหลัง + `install-autostart.bat` ให้ขึ้นเองตอนเข้า Windows + `stop-app.bat` ที่ใช้หยุดโดยตั้งใจเท่านั้น (ดูหัวข้อ 12.7) ส่วน Docker เก็บไว้เป็นโหมดเสริม
- **ระบบไม่เก็บข้อมูลรายงานไว้เลย** (stateless) คนถัดไปจึงไม่เห็นข้อมูลของคนก่อนในเซิร์ฟเวอร์ แต่ **ข้อมูลที่ค้างอยู่ในหน้าเบราว์เซอร์** ยังอยู่ ต้องมีปุ่ม "เริ่มรอบใหม่" และหน้าเว็บต้องแสดงวัน/รอบที่กำลังทำให้เห็นชัดเสมอ ป้องกันคนถัดไปส่งค่าผิดรอบ
- **ไฟล์ Excel ที่ดาวน์โหลดจะอยู่ในโฟลเดอร์ Downloads ของเครื่องกลาง** ซึ่งใครก็เห็นและอาจกดเลือกไฟล์ผิดตอนอัปโหลดไฟล์รอบก่อน (ใช้อ่านค่า H เดิม) → ชื่อไฟล์มีวันและเวลากำกับอยู่แล้ว ให้ UI แสดงชื่อไฟล์ที่เลือกและวัน/รอบที่อ่านได้จากไฟล์นั้น แล้วเตือนถ้าไม่ใช่รอบก่อนหน้าของวันเดียวกัน
- **ผู้ใช้หลายคนสลับกัน** ไม่ต้องมีระบบล็อกอิน แต่ถ้าต้องรู้ว่าใครส่งรอบไหน ให้เพิ่มช่อง "ผู้ส่งรายงาน" (ไม่บังคับ) ในอนาคต
- ตั้งให้ Windows ไม่เข้าโหมดสลีป/ไฮเบอร์เนตตอนไม่มีคนใช้ ไม่เช่นนั้นระบบอาจไม่พร้อมตอนเวรถัดไปมา

### 14.1 โครงสร้างไฟล์ Excel จริง
- มีชีตเดียว `Sheet1` ช่วง A1:M31
- แถว 1: รวมเซลล์ A1:H1 เป็นชื่อรายงาน / แถว 3: หัวตาราง (B3:C3 = "ทิศทาง / กำลังลม", D3:E3 = "ท้องฟ้า / ลักษณะอากาศ")

### 14.3 ตารางถอดความ (ย้ายไปไว้ใน `config.py`)

**ทิศลม** (dd คือทิศเป็นหน่วย 10 องศา) ข้อความในไฟล์จริงขึ้นต้นด้วย "ลม" เช่น "ลมตะวันออกเฉียงเหนือ" (กระดาษใช้คำว่า "ทิศ")

| dd | ชื่อทิศ |
|---|---|
| 35, 36, 01 | เหนือ |
| 02–07 | ตะวันออกเฉียงเหนือ |
| 08–10 | ตะวันออก |
| 11–16 | ตะวันออกเฉียงใต้ |
| 17–19 | ใต้ |
| 20–25 | ตะวันตกเฉียงใต้ |
| 26–28 | ตะวันตก |
| 29–34 | ตะวันตกเฉียงเหนือ |
| 00 | ลมสงบ (ยืนยันแล้ว แม้ ff>0; ช่อง C ว่าง) |
| 99 | แปรปรวน → "ลมแปรปรวน" |
| `//` | `n/a` (ตัวเลือกแรกใน dropdown; เตือนสีเหลือง เพราะเป็นค่าที่ถูกต้องเมื่อเครื่องวัดลมเสีย) |

**ยืนยันจาก dropdown ในไฟล์ Excel (คอลัมน์ B)** ตัวเลือกทั้งหมดคือ `n/a, ไม่ระบุ, ลมแปรปรวน, ลมสงบ, ลมเหนือ, ลมตะวันออกเฉียงเหนือ, ลมตะวันออก, ลมตะวันออกเฉียงใต้, ลมใต้, ลมตะวันตกเฉียงใต้, ลมตะวันตก, ลมตะวันตกเฉียงเหนือ` ข้อความในตารางข้างบนจึงใช้ได้ตรงตัว ("ไม่ระบุ" มีใน dropdown แต่ไม่ใช้ เพราะผู้ใช้ให้ dd=00 เป็น "ลมสงบ")

**คอลัมน์ C (กำลังลม):** dropdown คือ `/ไม่ระบุ, สงบ, / กำลังอ่อน, / กำลังปานกลาง, / กำลังแรง` แต่ข้อมูลที่กรอกจริงเว้นช่อง C ว่างเมื่อลมสงบ ให้ทำตามข้อมูลจริง

**กำลังลม** (นอต): 00 ลมสงบ / 01 และ 2–7 กำลังอ่อน (ลายมือในกระดาษเขียน "0-1 กำลังอ่อน") / 8–15 กำลังปานกลาง / ≥16 กำลังแรง

**ท้องฟ้า** (N): 0 ท้องฟ้าแจ่มใส / 1–2 ท้องฟ้าโปร่ง / 3–4 เมฆบางส่วน / 5–6 เมฆเป็นส่วนมาก / 7 เมฆมาก / 8 เมฆเต็มท้องฟ้า / 9 มองไม่เห็นท้องฟ้า

### 14.4 ตัวอย่างจริงที่ตรวจแล้ว (`IMG_1438.jpg`)
ข้อความ `AAXX 17094 / 48552 32460 60504 10311 20255 30088 40094 57006 81246 / 333 58014` ถอดได้
- `17094`: วันที่ 17, 09 UTC = 16.00 น., iw=4 (ความเร็วลมเป็นนอตอยู่แล้ว ไม่ต้องแปลง)
- `32460`: iR=3 (ไม่มีกลุ่มฝน → G = 0.0), iX=2 (ไม่มีกลุ่ม 7 → E ว่าง)
- `60504`: N=6 เมฆเป็นส่วนมาก, dd=05 ตะวันออกเฉียงเหนือ, ff=04 กำลังอ่อน
- `10311` → 31.1 °C, `20255` → จุดน้ำค้าง 25.5 °C
- ตรงกับค่าที่หน้าจอ METNET แสดง (31.1 / 25.5) และตรงกับที่กรอกในแถวนครศรีธรรมราชของ Excel (ลมตะวันออกเฉียงเหนือ / กำลังอ่อน, เมฆเป็นส่วนมาก) ใช้เป็น test case แรกได้เลย

**ตัวอย่างที่ 2 (`IMG_1451.jpg`, สงขลา 48568, 18-11-69 13.00 น.)**
`AAXX 18064 / 48568 01460 81003 10271 20239 30119 40127 57016 60051 70262 8387/ / 333 58019 60056 70270` และรหัสท้ายข่าว `48568 UU83 RR5.4 RD27.0 RO`
- `18064`: 06 UTC = 13.00 น., iw=4 (นอต) / `01460`: iR=0 (มีกลุ่มฝนทั้ง Section 1 และ 3), iX=1 (มีกลุ่ม 7)
- `81003`: N=8 เมฆเต็มท้องฟ้า, dd=10 ตะวันออก, ff=03 กำลังอ่อน / `10271` = 27.1 °C / `20239` = 23.9 °C
- `60051`: ฝน 005 = 5 มม. tR=1 (6 ชม.) ใน Section 1 / `70262`: ww=02 (< 04 จึง E ว่าง), W1=6, W2=2
- `333 ... 60056`: ฝน 005 tR=6 (2 ชม.) / `70270`: ฝน 24 ชม. = 27.0 มม.
- ไฟล์ Excel 13.00 น. แถวสงขลา: ลมตะวันออก / กำลังอ่อน, เมฆเต็มท้องฟ้า, E ว่าง, 27.1, **G = 5, H = 5.4** — ทุกค่ายกเว้น G/H ตรงกับกฎที่ตกลงกัน

### 14.5 ข้อมูลจริงที่ขัดกับสมมติฐานเดิม (ต้องตัดสินก่อนเขียน `rain.py` และ `excel.py`)

**(ก) มีรอบ 07.00 น. ด้วย (ผู้ใช้ยืนยันแล้ว รวมเป็น 4 รอบ)** โฟลเดอร์มีไฟล์ `รายงานผลการตรวจอากาศเวลา 07.00 น. 18-11-69.xlsx` ที่กรอกข้อมูลครบ
- ในไฟล์ 07.00 ค่าในคอลัมน์ H เป็นตัวเลขใหญ่ (เช่น นครศรีธรรมราช 44.6, สงขลา 21.8, นราธิวาส 28) ซึ่งเข้ากับ **ฝน 24 ชม.** ไม่ใช่ฝนสะสมตั้งแต่ 07.00 น.
- เทมเพลตเตรียมรองรับไว้แล้ว: dropdown ที่ H3 ให้เลือก "ฝน 24 ชม. (มม.)" หรือ "ฝนสะสมวันนี้ (มม.)" และ dropdown ที่ B25 มีหมายเหตุท้ายตาราง 2 แบบ (แต่ไฟล์ 07.00 ที่ส่งมายังเป็นหัว "ฝนสะสมวันนี้" อยู่ อาจลืมสลับ)
- ถ้ารอบ 07.00 เป็นรอบจริง: G = ฝน 3 ชม., H = ฝน 24 ชม. (กลุ่ม `7RRRR` ใน Section 3 / `RD` ท้ายข่าว) และระบบต้องสลับหัวคอลัมน์ H กับหมายเหตุท้ายตารางให้ด้วย

**(ข) ค่า G และ H ในไฟล์ไม่ได้มาจากกฎ tR=7 และ "H เดิม + G" ล้วน ๆ**
- เทียบไฟล์ 10.00 กับ 13.00 (H เดิม + G = H ใหม่): ตรง 20 จาก 21 สถานี ยกเว้น **พัทลุง** (10.00 น. H = 20.8, 13.00 น. G = 7.5 → ควรได้ 28.3 แต่ในไฟล์ H = 36.2) แสดงว่าบางค่าไม่ได้คำนวณจาก H เดิม
- **สงขลา 13.00 น. ข้อความไม่มีกลุ่ม tR=7 เลย** (มี tR=1 และ tR=6) แต่ในไฟล์ G = 5 และ H = 5.4 ตรงกับช่องใน METNET: "ปริมาณฝน 3 ชม. = 5" และ "ฝนตั้งแต่ 00 UTC = 5.4" (5.4 มาจาก `RR5.4` ในรหัสท้ายข่าว)
**ตัดสินแล้ว (จากผู้ใช้):** ค่า **F (อุณหภูมิ), G (ฝน 3 ชม.), H (ฝนตั้งแต่ 00 UTC / รอบ 07.00 คือฝน 24 ชม.)** ใช้ค่าที่ส่วนเฝ้าระวังกรอกไว้ในเว็บ METNET ได้เลย ไม่ต้องถอดจากรหัสและไม่ต้องคำนวณ H เอง

ผลต่อการออกแบบ
- **แบ่งที่มาข้อมูล 2 ส่วน:** B, C, D, E (ทิศลม กำลังลม ท้องฟ้า ลักษณะอากาศ) ถอดจากรหัส SYNOP ตามหัวข้อ 5.0 / F, G, H มาจากค่าใน METNET
- **ข้อดี:** ตัดงานที่เสี่ยงที่สุดออก (เลือกกลุ่ม tR ผิด, `RR` ในรหัสท้ายข่าว, สูตรฝนสะสม) ค่าตรงกับที่ส่วนเฝ้าระวังตรวจแล้ว (รวมกรณีที่เขาแก้ไขค่าหลังส่งข่าว)
- **ข้อเสีย:** ค่า F/G/H ไม่อยู่ในข้อความรหัสที่วาง ผู้ใช้ต้องนำเข้าจากหน้า METNET (พิมพ์เอง หรือวางจากตารางถ้าหน้าเว็บมีตารางรวม) วิธีนี้ยังต้องดูหน้าเว็บจริงก่อนออกแบบ
- **ตาข่ายนิรภัย:** ตรวจ H เดิม + G เทียบกับ H เป็นการเตือน (ตัวอย่างจริง: ตรวจพบพัทลุง 13.00 น. ที่ตัวเลขไม่ลงรอยกัน) และเตือนเมื่อ F ที่กรอกต่างจาก `1sTTT` ในรหัสข่าว
- **งานที่ลดลง:** `rain.py` เหลือแค่รับตัวเลข/`T`/`-` และตรวจความสอดคล้อง ไม่ต้องถอด RRR เป็นค่าหลัก
- **รอบ 07.00:** H = ฝน 24 ชม. ระบบสลับหัวคอลัมน์ H3 เป็น "ฝน 24 ชม. (มม.)" สลับหมายเหตุท้ายตาราง (B25) เป็นแบบ "ฝน 24 ชม. หมายถึง ..." และใส่เวลาในกล่องข้อความเป็น 07.00 น. ส่วนรอบอื่นใช้ "ฝนสะสมวันนี้ (มม.)" ตามเดิม

- เลือกวันที่ และชั่วโมงเป็น **UTC** (เช่น `06` = 13.00 น. เวลาไทย) หน้าแสดงสถานีของทั้งประเทศ (เราใช้เฉพาะ 21 สถานีภาคใต้ฝั่งตะวันออก) เป็นปุ่มเลขท้าย 3 หลักของรหัสสถานี (เช่น 568 = 48568) จัดเป็น 6 กลุ่มตามฉบับข่าว **ไม่มีตารางรวมค่าของทุกสถานี** ผู้ใช้ต้องกดทีละปุ่มเพื่อเข้าหน้ารายละเอียด
- ป้ายสีน้ำเงินหน้าแต่ละกลุ่มเขียนว่า "ดูฉบับ SMTHxx/SITHxx" (ยังไม่ทราบว่ากดแล้วแสดงข้อความฉบับข่าวทั้งฉบับหรือไม่ ดูข้อตรวจสอบด้านล่าง)

**สถานีของเราอยู่กระจายใน 6 กลุ่ม** (อ่านจากภาพ ตรวจอีกครั้งตอนใช้งานจริง)

|---|---|---|
| SMTH01/SITH20 | 48500, 48551, 48569, 48583 | 4 |
| SMTH02/SITH21 | 48475, 48517 | 2 |

**หน้ารายละเอียดรายสถานี** (`.../Record_data/Send_News3Hr_detail/2026-11-18%2006:00:00/119` ซึ่งวันที่และชั่วโมงเป็น UTC ส่วนเลขท้ายเป็นเลขภายในของสถานี ไม่ใช่รหัส 48568)
- มีทุกค่าที่รายงานต้องใช้ในหน้าเดียว: อุณหภูมิตุ้มแห้ง, ทิศลม (เป็นองศา เช่น `100`), ความเร็วลม (นอต), ปริมาณฝน 3 ชม., ฝนตั้งแต่ 00 UTC, ww
- กล่อง "รหัสข่าว" (ข้อความ `AAXX ...`) และกล่อง "รหัสท้ายข่าว" (เช่น `48568 UU83 RR5.4 RD27.0 RO` ซึ่ง `RR` = ฝนตั้งแต่ 00 UTC และ `RD` = ฝน 24 ชม. ตรงกับช่องบนหน้าจอ)
- ดังนั้นการกรอกทั้งรอบเท่ากับเปิด 21 หน้า (วิธีเดิมที่ผู้ใช้ทำอยู่)

**ข้อตรวจสอบก่อนออกแบบหน้านำเข้า (ผู้ใช้ลองแล้วถ่ายภาพ/ก๊อปข้อความมาให้ดู)**
1. กดป้าย "ดูฉบับ SMTH40/SITH40" แล้วขึ้นอะไร ถ้าเป็นข้อความฉบับข่าวทั้งฉบับ ผู้ใช้ก๊อป 6 ฉบับก็ได้ครบ 21 สถานี (ไม่ต้องเปิด 21 หน้า)
2. ในหน้ารายละเอียดรายสถานี กด Ctrl+A แล้ว Ctrl+C แล้ววางใน Notepad ได้อะไร (ค่าในช่องกรอก/กล่องข้อความอาจไม่ถูกคัดลอกตามมา)

**แนวทางนำเข้าที่เตรียมไว้ (เลือกตามผลตรวจสอบ)**
- **แบบ ก (ฉบับข่าวทั้งฉบับ ถ้าข้อ 1 ได้):** วางข้อความทั้ง 6 ฉบับ ระบบเลือกเฉพาะ 21 สถานีของเรา ได้ B–F ทั้งหมด ส่วน G/H ต้องหาจากรหัสท้ายข่าวหรือกรอกเพิ่ม
- **แบบ ข (รายสถานี):** ผู้ใช้ก๊อปกล่อง "รหัสข่าว" (และ "รหัสท้ายข่าว") จากแต่ละหน้ามาวางต่อกันในช่องเดียว ระบบอ่านหลายข้อความได้อยู่แล้ว ได้ B–F และ H (จาก `RR`/`RD`) ผู้ใช้พิมพ์เฉพาะ G
- **แบบ ค (กรอกเอง):** ตารางตรวจทานมีช่อง F/G/H ให้พิมพ์ ใช้เป็นทางสำรองเสมอ
- ทุกแบบต้อง **ข้ามสถานีนอกรายงานอย่างเงียบ ๆ** เพราะฉบับข่าวฉบับเดียวมีหลายสิบสถานี ไม่แจ้งเตือนทีละสถานี
